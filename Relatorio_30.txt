4. PROPOSTA PARA MISSAO 23

Missao 23 — Politica de Erros HTTP 4xx no Outbox

Escopo minimo:
- Quando o backend retornar 400, 401, 403 ou 422, marcar a operacao como
  FALHA_DEFINITIVA (nao mais PENDENTE)
- Operacao com falha definitiva e removida da fila e registrada para auditoria visual
- Erros 429 (rate limit), 500, 502, 503 continuam como PENDENTE (retry)
- UI minima: indicador visual na TelaPrincipal mostrando quantidade de
  operacoes com falha

Justificativa:
- Seguranca + Integridade. Operacoes recusadas definitivamente pelo backend
  (403 token expirado, 422 payload invalido) ficam pendentes para sempre e
  bloqueiam operacoes seguintes na fila. O usuario sincroniza indefinidamente
  sem saber que suas operacoes estao permanentemente recusadas.
