5. RECOMENDACAO: MISSAO 24

5.1. Por que esta missao primeiro:
- E o gatilho que destrava todas as outras
- Sem um cliente HTTP para chamadas GET, nenhuma tela pode mostrar dados reais
- E infraestrutura pequena e isolada: um arquivo ApiService com 3-4 metodos
- Nao altera regras de negocio, nao adiciona dependencias, nao toca no backend
- Pode ser testada com transporte injetavel ( padrao ja estabelecido)
- O ServicoSessao.tokenAtual ja existe e esta integrado

5.2. Escopo minimo:
- ApiService com metodos:
  * listarMinhasColetas() → GET /api/v1/collections
  * obterColeta(id) → GET /api/v1/collections/{id}
  * listarDisponiveis() → GET /api/v1/collections/disponiveis
- Cada metodo retorna o modelo JSON do backend (Map<String, dynamic>)
- Transporte HTTP injetavel (testes sem servidor)
- Token obtido de ServicoSessao.tokenAtual em tempo de chamada
- Testes unitarios cobrindo: sucesso (200), 401, erro de rede

5.3. Nao incluir:
- UI (telas)
- Escrita/criacao (isso e Missao 25)
- Modificacoes no backend
- Novas dependencias
